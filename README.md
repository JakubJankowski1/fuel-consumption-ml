# Fuel Consumption Prediction (Auto MPG)

A small, reproducible machine-learning analysis of historical car fuel consumption. This is a focused portfolio version of a university project; the original analysis logic is retained with only path and headless-plot changes.

## What it does

- Explores car specifications and fuel consumption with histograms, correlations, and origin counts.
- Converts fuel economy from miles per US gallon (MPG) to litres per 100 km (`235.214583 / MPG`) and displacement from cubic inches to cm³.
- Drops records with missing values, one-hot encodes vehicle origin, and makes a reproducible 80/20 random train/test split (`random_state=42`).
- Compares linear regression, an unrestricted decision tree, and a decision tree selected by five-fold `GridSearchCV` on the training set. Reports train/test R² and test MAE/RMSE; saves CSV and PNG charts to `outputs/`.

The model predicts **historical, city-cycle fuel consumption**, not modern real-world fuel costs or emissions. No API, deployed model, or interactive prediction app is included.

## Requirements and Windows setup

Use Python **3.12**. In PowerShell, from this repository's directory:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

The four direct dependencies are NumPy, pandas, Matplotlib, and scikit-learn. `requirements.txt` pins the versions used for the verified run. These commands assume `python` resolves to Python 3.12; check with `python --version` first. A clean Python 3.12.7 virtual environment was created and the pinned dependencies were installed successfully; `pip check`, the tests, and the complete analysis passed. In the restricted verification environment, `ensurepip` initially failed because its temporary directory was unwritable. Pointing `TEMP` and `TMP` to a writable directory resolved that environment-specific issue.

## Get the data

Download the official **`auto-mpg.data`** file from the [UCI Auto MPG dataset page](https://archive.ics.uci.edu/dataset/9/auto), or directly from [UCI's data file](https://archive.ics.uci.edu/ml/machine-learning-databases/auto-mpg/auto-mpg.data). Save it as `data\auto-mpg.data`, then convert it:

```powershell
.\.venv\Scripts\python.exe prepare_data.py data\auto-mpg.data
```

This creates `data\Automobile.csv` in the format expected by the analysis. The converter expects the standard 398-record UCI file, maps origin codes 1/2/3 to `usa`/`europe`/`japan`, and leaves the six unknown horsepower entries blank. It uses only the Python standard library. Neither raw nor converted data is committed.

The official UCI file was downloaded for verification (SHA-256: `48b830e11feee5572525f8f1691ddb9d38d3d7b7063edcd8fca672c2a5e17d8d`). Its converted CSV matches the original student project's CSV value-for-value across all 398 rows and nine columns; textual numeric formatting and the inferred `weight` dtype differ. Neither dataset file is redistributed here. UCI licenses Auto MPG under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); cite: Quinlan, R. (1993), *Auto MPG*, UCI Machine Learning Repository, [doi:10.24432/C5859H](https://doi.org/10.24432/C5859H). The repository's data-preparation code does not imply ownership of the dataset.

## Run

```powershell
.\.venv\Scripts\python.exe fuel_consumption_analysis.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

The first command prints the data profile and model metrics and writes `outputs\model_comparison.csv` plus seven charts. The tests currently cover the UCI text-file parser, **not** the ML model's statistical validity. `outputs/`, `data/`, `.venv/`, and IDE files are git-ignored.

## Verified results

The table is from an actual local run on a CSV freshly converted from UCI's `auto-mpg.data`, using a clean Python 3.12.7 environment with NumPy 2.4.3, pandas 3.0.1, Matplotlib 3.10.8, and scikit-learn 1.8.0. The CSV contains 398 rows and nine columns; six rows have missing horsepower and are dropped, leaving 392 rows. The generated comparison CSV and example R² chart are byte-for-byte identical to the previously saved examples.

| Model | Train R² | Test R² | Test MAE (L/100 km) | Test RMSE (L/100 km) |
| --- | ---: | ---: | ---: | ---: |
| Linear regression | 0.8849 | **0.8899** | **0.9814** | **1.2497** |
| Decision tree | 1.0000 | 0.8187 | 1.1686 | 1.6036 |
| Grid-searched decision tree | 0.9635 | 0.7680 | 1.1211 | 1.8137 |

The selected tree parameters were `max_depth=None`, `min_samples_leaf=2`, and `min_samples_split=10`; its five-fold training CV R² was 0.8370. On this held-out test set, grid search **did not** improve the tree's R² or RMSE. The unrestricted tree's perfect training R² and lower test R² indicate overfitting. Linear regression had the best test results among these three models on this one split.

See the [saved comparison CSV](examples/model_comparison.csv) and [R² chart](examples/model_r2_comparison.png), generated by the same run. Running the script generates the complete set of charts locally.

## Limitations

- A single random 80/20 split is sensitive to the sample; there is no repeated external validation or confidence interval.
- Hyperparameters are selected with training-only cross-validation, but the final comparison uses one small test set. The separate tree model does not beat the linear baseline.
- Complete-case deletion removes six vehicles. One-hot encoding is done before splitting; this does not use target values but a production pipeline would fit preprocessing on training data only.
- The underlying cars are from model years 1970–1982. The model is educational and should not be used for contemporary vehicles or operational decisions.
- The code remains a single analysis script; it has no model serialization, inference interface, CI, or end-to-end regression tests.
